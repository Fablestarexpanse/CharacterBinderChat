## Fixed the same day

All findings are fixed: the high and medium ones first, then the low ones. Each was checked by
running it, not only by reading the change:

- **H1, M2** — the voice server refuses requests with no token (403), a wrong token (403) and a rebound `Host`
  (403); a page cannot reach it directly; `GET /api/voice/voices` reports `running: false` and does not start it.
- **H2, M9, M10, M11, M15** — jobs are acknowledged and resent once if lost to an idle exit; the worker exits when
  its parent dies; vocal isolation runs in its own short-lived process; uploads decode at most 60 s and are trimmed
  before isolating; voice metadata is read defensively and every handler answers `{ ok: false, error }`; `stopServer`
  asks the server to shut down (`/v1/shutdown`) and kills it after 5 s.
- **H3** — the abort controller exists before the prompt is assembled. Ringing in, answering and hanging up after
  0.3 s left the chat with "started" and "ended" and no late reply.
- **M1** — a test with a changed address or service no longer gets the stored key.
- **M3** — `voice:runtime` and `media:saveFolder` are `MACHINE_KEYS`: left out of new backups, and the live values
  kept on restore (`tests/unit/backup.test.mjs`).
- **M4, L6** — `*not*` keeps its word; `*nods*` at a sentence start is dropped; bad `cfg` is a 400, not a 500.
- **M5** — answering while a reply is being written stops it first; the answered "started" line carries `outreach`
  (observed: `outreach: "repair"`).
- **M6** — `generateAssistantReply` returns whether it wrote a reply; outreach announces only then, and re-checks
  for a call or a reply in progress after its network wait.
- **M7** — from the upload until the reply starts, the composer shows "Sending your picture…", and Send, Call,
  lines on a call and outreach all wait.
- **M8** — on a Redo the review's button is **Keep this one** and only closes the review.
- **M12** — the voice routes use the envelope.
- **M13** — AGENTS.md now says what the fixtures are for (builders from before templates); new prompts are covered
  by the test that checks each declares exactly the variables it uses.
- **M14, L11** — AGENTS.md has a voice paragraph and the audio/video asset types; README describes voice setup;
  `plan-voice.md` no longer says voices are on cards.
- **L7** — the ringtone does not start for a call answered or declined while settings loaded; Call cannot be
  double-clicked into two calls; the phone menu counts only chats that exist; Regenerate after hanging up does not
  use the phone prompt (`tests/unit/channel.test.mjs`).

Then the low findings:

- **L2** — voice setup installs exact versions: uv 0.6.14 from its official installer, checked by SHA-256 before it
  runs (only when uv is not already installed); torch/torchaudio 2.11.0; the engine's libraries at the versions it
  was proven with; the model, tokenizer and isolation model at fixed Hugging Face revisions. Against the existing
  install every pinned step resolves to what is there ("Would make no changes"; no file downloaded again).
- **L3** — `which()` skips empty and relative PATH entries and looks only for `.exe` on Windows.
- **L4** — upstream replies are read with caps (`readBodyCapped` / `readJsonCapped`: 4 MB JSON, 64 KB error text,
  25 MB audio and images, 200 MB clips); an image address handed back by a service is fetched only if it is http(s);
  `/api/voice/speak` and `/api/vision/describe` cap their request bodies (observed: 300 KB refused with
  `{ ok: false, error }`, non-JSON a 400).
- **L5** — a clip must carry a video brand in its `ftyp` box (HEIC and AVIF are refused); MP3 without a tag needs a
  valid frame header. The three stored clips are `isom` and still pass. Media-folder copies of audio get `.wav` etc.
- **L8** — Try again on a photo or clip whose character was deleted fails with that reason.
- **L9** — turning both contact switches off keeps the character's call, timing and limit settings.
- **L10** — preview addresses are released when replaced or unmounted; a staged picture belongs to the chat it was
  staged in (checked in code; switching chats with one staged was not tried in the browser).
- **L11** — banners documented as non-card fields; the demo voice list exists once (`lib/media/voice.ts`).
- **L12** — `tests/unit/voiceSpeak.test.mjs`: demo voices need no server, a sample is registered once and reused,
  every request carries the token, a server with another token is refused, and `inflight` marks clear on failure.

After the fixes: `tsc` and `lint` clean, `npm test` 535 pass, 0 fail, 2 skipped. Nothing from the audit is open.

## High

| # | Where | What goes wrong | Fix |
|---|---|---|---|
| H1 ✔ | `voice/fable_voice/server.py` (no Host/Origin/token check) | Any web page can reach the voice server on `127.0.0.1:7861`: text/plain POSTs are accepted (queue GPU jobs, upload voices, unload the model), and with DNS rebinding a page can read the voice list and make audio in a user's cloned voice. FableChat's proxy does not cover this port. | Refuse any Host but `127.0.0.1:<port>`/`localhost:<port>`, and require a random token header that FableChat passes to the child in its environment. |
| H2 ✔ | `server.py` `Engine.speak` / `worker.py` idle exit | A line that arrives while the worker is exiting for idleness goes into a dead queue; the request waits up to 30 min holding the engine lock, so every other line waits too. A worker crash mid-job does the same; the load wait (900 s) likewise. | Poll the response queue with a short timeout, check `proc.is_alive()`, restart once if the job was never picked up; drain the request queue before the worker exits. |
| H3 ✔ | `lib/chat/calls.ts` `hangUp` with `generation.ts` (abort controller set only after `assemblePrompt`) | Hanging up before the first word does not stop the reply: it streams in after "Call · 0:02" as a line "on the call". | Create and store the AbortController before `assemblePrompt`; check `signal.aborted` before adding the reply. |

## Medium

| # | Where | What goes wrong | Fix |
|---|---|---|---|
| M1 ✔ | `app/api/media/test/route.ts` | A test with a saved connection's id but a different `baseUrl` sends the saved key (Authorization / xi-api-key) to the new host. Same-origin only, but the key stops being bound to the host it was entered for. (Predates today.) | Use the stored key only when the base URL matches the saved one; otherwise require the key again. |
| M2 ✔ | `app/api/voice/voices` GET → `ensureRunning()`; `access.ts` checks Origin only on writes | A cross-site `<img src=".../api/voice/voices">` starts the voice server (and, with H1, leaves it reachable). | Do not start the server from a GET (return the list only when it is already up), or refuse `sec-fetch-site: cross-site` there. |
| M3 ✔ | backups keep all `app_kv` but `secret:*` | Restoring an untrusted backup with a crafted `voice:runtime` (`installed: true`, `folder: \\host\share`) makes FableChat run that folder's `python.exe` on the next spoken line: code execution, and NTLM leaks over SMB. `port` can also redirect voice samples. | On restore, drop `voice:runtime` and `media:saveFolder` (or set `installed: false` and ask to confirm setup again). |
| M4 ✔ | `server.py` `clean_line` | `*…*` is treated as an action and deleted, so emphasis flips meaning: "I did \*not\* do it" is spoken as "I did do it". | Drop only multi-word `*…*` spans or ones that start a sentence; otherwise just remove the asterisks. |
| M5 | `lib/chat/calls.ts` `answerCall` | Answering while a reply is streaming leaves a silent call (the reply generator returns early); the answered call also carries no `outreach`, so it does not count toward limits. | Stop the current reply first (or refuse to answer while generating); put `outreach` on the answered "started" line. |
| M6 | `lib/outreach/runner.ts` | If you send a message while a tick is fetching core memory, no text is written but `announce()` still chimes, marks unread and shows your own last line (or a "Response failed" text). | Have `generateAssistantReply` report whether it produced a reply; announce only then; re-check `isGenerating` / `call` just before acting. |
| M7 | `lib/chat/userPictures.ts`, `ChatInput.tsx` | While a sent picture is uploading/being read, sending another message (or calling) answers without the picture; the picture's own reply then lands late, possibly on a call. | Hold a "sending" state from upload until the reply starts; disable send and Call meanwhile. |
| M8 ✔ | `components/chat/Attachments.tsx` | Redo opens the review card on a ready photo/clip; its **Skip** removes the whole attachment, earlier takes included, with no Undo. | When the attachment already has a picture, Skip just closes the review. |
| M9 | `voices.py` vocal isolation in the HTTP process | Isolation runs outside the engine lock in the server process, which keeps a CUDA context afterwards (part of the GPU memory is never given back) and can run out of memory beside a generation. | Run isolation in the worker or a short-lived process. |
| M10 | `server.py` / `voices.py` uploads | The 25 MB cap counts compressed bytes; a low-bitrate file can decode to hours of audio, all isolated and resampled before the 30 s trim. | Check frames first, trim before isolating. |
| M11 | `voices.py` `list()`, `do_GET` | One corrupt voice `.json` makes `/health` drop the connection; FableChat then thinks the server is down and starts a second one. | Read metadata defensively and wrap the handlers. |
| M12 | `app/api/voice/voices/route.ts` | Passes the voice server's `{error}` through with its status; misses `{ ok: false, error }` (DELETE 404 returns `{ ok: false }` with no error). AGENTS.md: "every non-2xx body is { ok: false, error }". | Map non-2xx to `{ ok: false, error }`, success to `{ ok: true, voice }`. |
| M13 | `lib/prompts/defaults.ts` | Five new prompts (phone-call, call-outreach, image.describe, video.clip, video.reference-clip) have no fixture, as AGENTS.md asks (the older text/outreach/photo prompts already lacked one). | Add render fixtures, or state in AGENTS.md that fixtures are for builders that existed before templates. |
| M14 | AGENTS.md / README | No AGENTS paragraph on voice (fields, consent, `/api/voice/*`, `voice:runtime`); README still calls voice "planned" and does not mention VibeVoice setup. | Document both. |
| M15 | `voiceRuntime.ts` `child.kill()` on Windows | Killing the server while a job runs orphans the worker, which keeps GPU memory until the job ends plus the idle time; after a hot reload `stopServer` cannot kill the server process at all (it only unloads the model). | Worker checks its parent is alive; record the server PID (or add `/v1/shutdown`) and use it. |

## Found fine

Every new route calls `guard()` and is under the proxy matcher. Spawns use `shell: false` with argument arrays.
Media-folder names are single safe segments and cannot leave the folder. Voice ids cannot escape the voices folder.
The OpenRouter key only goes to openrouter.ai. Pictures and voice samples are read from the asset store, never from
the request. Uploads are capped while streaming. Range replies are correct. Assets referenced by banners, voices,
clips and earlier takes are counted by the garbage collector. Backups still strip `secret:*`. No component imports
`lib/server` or `lib/db`. The VibeVoice calls match the package (speaker numbering, streamer, sample rate). Old
saved chats and settings without today's fields load safely.
